# 성능 검사 — 데이터 로드부터 화면 표시까지

[← 문서 목차](../README.md) · 배포 구조는 [deploy.md](../deploy.md)

2026-09-25 22:00 KST, 운영(https://timesheet-brown-ten.vercel.app)을 서울의 개발 PC 에서 쟀다.

## 결론

- **요청 하나에 약 210~250ms 가 든다. 대부분은 네트워크 거리다.** DB 를 거치지 않는 `/health` 도 중앙값이 214ms 다. 응답 헤더 `x-vercel-id: icn1::iad1` 은 서울 엣지로 들어와 미국 동부(iad1) 함수에서 처리됐다는 뜻이고, DB(Neon)도 us-east-1 이다. DB 쿼리가 더하는 시간은 요청당 10~40ms 다.
- **화면이 데이터를 그리기까지는 API 를 두세 번 차례로 부르는 만큼 걸린다.** `/users/me`(로그인 확인)가 끝나야 화면 데이터를 부르므로 최소 두 번이고, 사장 멤버 화면은 세 번이다.
- **HTML·JS 는 빠르다.** HTML 은 미리 렌더된 정적 파일이라 TTFB 13~31ms, JS 는 첫 방문 기준 11~12개·압축 175~202KB 다.
- **레이아웃 이동(CLS)은 측정한 5개 화면 모두 0 이다.** 스켈레톤이 불러온 뒤와 같은 크기로 자리를 잡는다.

## 5. 측정하지 못한 것

- **FCP·LCP**: 측정 탭이 화면 뒤에 가려진(hidden) 상태라 paint 기록이 남지 않았다. 표 3 의 데이터 도착 시점으로 대신했다.
- **멤버 화면 실측**: 브라우저에 멤버 세션이 없어 표 1(API 부팅 순서)로 대신했다. 사장 화면은 이 브라우저에 이미 로그인돼 있던 세션으로 쟀다(비밀번호 입력 없음, 읽기만).
- **느린 모바일 회선**: 개발 PC 의 유선 회선에서 쟀다. 4G 에서는 왕복 시간이 더 커진다.

## 6. 다시 재는 법

```bash
# API (운영 DB 에 @test.dev 멤버·기록을 만들고 잰다 — 끝나면 지운다)
cd server && DATABASE_URL=<운영> N=10 pnpm exec tsx scripts/perf-boot.mts
```

화면 측정은 운영 페이지를 연 탭에서 iframe 으로 각 화면을 5회 열고 `performance.getEntriesByType("navigation" | "resource")` 와 `layout-shift` 를 읽었다.
