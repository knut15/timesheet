# 12. 멤버 오늘 근무 대시보드

[← PRD 개요](README.md) · 출퇴근은 [01](01-attendance.md) · 급여는 [02](02-pay.md) · 요청은 [08](08-correction-requests.md)·[09](09-leave-substitution.md)

## 목표

멤버가 앱을 열었을 때 첫 화면(출퇴근 탭)에서 **오늘 근무를 한눈에** 본다 — 지금 근무 중인지, 오늘 몇 시간 했는지, 이번 주·이번 달이 어디까지 왔는지, 처리할 것이 있는지.

## 위치

출퇴근 탭의 **시계(현재 시각) 바로 아래** (2026-09-25 사용자 결정 "출퇴근 탭에서 시간 하단에 만들어줘").

## 보여 줄 것 (있는 데이터만)

| ID | 무엇 | 데이터 |
|---|---|---|
| T-1 | 지금 상태 — 출근 전 / 근무 중(출근 시각·경과) / 오늘 퇴근함 / 오늘 휴가·대타로 쉼 | 오늘 기록, absences |
| T-2 | 오늘 근무 합계 — 여러 번 찍었으면 합, 오늘 기록 목록 | `/api/shifts/me` |
| T-3 | 이번 주 — 근무 시간 / 1주 소정근로시간, 근무한 날 / 소정근로일수, 주휴 상태(개근·진행 중·대상 아님) | `pay.ts computeWeek` |
| T-4 | 이번 달 예상 급여(세전) — 합계와 내역 링크 | `pay.ts computeMonth` |
| T-5 | 처리할 것 — 받은 대타 요청 수, 내 대기 요청 수 | `/api/requests/me` |
| T-6 | 출근 버튼과 매장 50m 알림 — 지금 있는 것 유지 | [04](04-geofence-notification.md) |

## 범위 밖

- 오늘 근무 **예정**(몇 시 출근 예정) — 앱에 근무 일정 데이터가 없다
- 동료가 지금 근무 중인지 — 멤버는 본인 것만 본다([10](10-calendar.md) CAL-7 과 같은 원칙)

## 수용 기준

| ID | 기준 |
|---|---|
| TD-1 | 출근 전·근무 중·퇴근 후·휴가일 네 상태가 서로 다르게 보인다 |
| TD-2 | 오늘 두 번 나눠 일하면 합계가 둘의 합이다 |
| TD-3 | 이번 주·이번 달 숫자가 급여 탭과 같다 (같은 `pay.ts`) |
| TD-4 | 받은 대타 요청이 있으면 대시보드에서 요청 탭으로 갈 수 있다 |
| TD-5 | 390px 에서 가로 스크롤 없음 |
