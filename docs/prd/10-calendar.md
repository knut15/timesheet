# 10. 근무 달력

[← PRD 개요](README.md) · 기록은 [01](01-attendance.md) · 수정 요청은 [08](08-correction-requests.md) · 휴가·대타는 [09](09-leave-substitution.md)

## 목표

근무 기록을 목록이 아니라 **달력**으로 본다. 한 달의 근무 패턴, 빈 날, 휴가·대타를 한눈에 보게 한다.

| 누가 | 무엇이 보이나 |
|---|---|
| 마스터 | **전체 멤버**의 근무 — 날마다 누가 일했는지, 몇 명·몇 시간인지 |
| 멤버 | **본인** 근무 기록만 |

## 요구사항

| ID | 요구 | 수용 기준 |
|---|---|---|
| CAL-1 | 월 달력 | 한 달을 주 단위 격자로 보인다. **주는 월요일에 시작**한다 (급여의 주 경계와 같다, [02](02-pay.md)). 이전·다음 달로 넘긴다 |
| CAL-2 | 날짜 칸 | 그날 근무가 있으면 표시한다. 멤버: 근무시간 합. 마스터: 일한 멤버 아바타(4명 이상이면 2명 + `+N`)와 시간 합. 정확한 인원 수는 칸의 읽는 이름과 상세 머리에 둔다 (칸 폭 약 44px) |
| CAL-3 | 휴가·대타 | 승인된 휴가(유급·무급)와 대타(쉰 쪽)를 근무와 구별해 표시한다 |
| CAL-4 | 진행 중 | 퇴근을 안 찍은 기록이 있는 날을 구별해 표시한다 |
| CAL-5 | 날짜 선택 | 날짜를 누르면 그날의 상세가 달력 아래에 나온다 — 기록(출근·퇴근·시간), 휴가·대타. 멤버는 여기서 [수정 요청](08-correction-requests.md)을 할 수 있다 |
| CAL-6 | 오늘 | 오늘 날짜를 구별한다. 처음 열면 이번 달, 오늘이 선택돼 있다 |
| CAL-7 | 권한 | 멤버 달력에는 다른 멤버의 기록이 절대 보이지 않는다 (서버가 본인 것만 준다 — `/api/shifts/me`, `/api/absences/me`) |
| CAL-8 | 폭 | 390px 에서 가로 스크롤 없이 7칸이 들어간다. 칸 안 글자는 줄여도 날짜를 누를 수 있어야 한다(터치 영역 40px 이상) |
| CAL-9 | 접근성 | 날짜 칸은 버튼이고, 읽는 이름에 날짜와 요약(예: "9월 22일, 4시간 근무")이 들어간다. 선택된 날은 `aria-pressed` |

## 진입점

| 누가 | 어디 |
|---|---|
| 멤버 | 기록 탭 — 달력이 기본, 목록으로 바꿔 볼 수 있다 |
| 마스터 | 하단 내비 **달력** (`/admin/calendar`) — 내비는 `대시보드 · 달력 · 요청 · 멤버 · 매장`. 초대는 멤버 화면 안으로 옮긴다(`/admin/invites` 경로는 유지, 멤버가 활성). 근거는 [디자인 명세](../design/calendar.md) 1절 |

## 데이터

새 API 는 없다.

| 누가 | 호출 |
|---|---|
| 멤버 | `GET /api/shifts/me?from&to`, `GET /api/absences/me?from&to` (기존) |
| 마스터 | `GET /api/stores/me/dashboard?month=YYYY-MM` — 멤버·기록·absences 를 이미 준다 (기존) |
| 마스터 (대기 표시) | `GET /api/stores/me/requests` — `status === "pending"` 인 수정 요청 (기존) |

## 범위 밖

- 근무 예정(스케줄) 표시 — 앱에 근무 일정 데이터가 없다
- 달력에서 기록을 끌어 옮기기
