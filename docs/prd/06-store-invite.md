# 06. 매장과 초대 코드

[← PRD 개요](README.md) · 로그인은 [05-auth.md](05-auth.md) · 마스터 화면은 [07-admin.md](07-admin.md)

## 목표

마스터(사장)가 매장을 만들고 멤버(알바생)를 초대 코드로 불러들인다.
멤버는 가입한 뒤 초대 코드를 등록하면 그 매장 소속이 되고, 출퇴근 기록이 매장에 쌓인다.

## 역할

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| 마스터 | 매장을 만든 사람 | 매장 설정, 초대 코드 발급·취소, 멤버 급여 조건 설정·퇴사처리, 멤버 근무 기록 수정·삭제, 대시보드 |
| 멤버 | 초대 코드를 등록한 사람 | 자기 출퇴근, 자기 기록·급여 보기 |

- 한 사용자는 **매장 하나에만** 속한다 (마스터든 멤버든). 여러 매장은 다음 단계.
- 멤버는 자기 기록을 고치거나 지울 수 없다. 잘못 찍었으면 마스터가 고친다.

## 흐름

```
마스터: 가입 → /onboarding "매장 만들기" → /admin → 초대 코드 발급 → 코드를 알바생에게 전달(앱 밖)
멤버:   가입 → /onboarding "초대 코드 입력" → 매장 소속 → / (출퇴근 화면)
```

## 초대 코드

| 항목 | 규칙 |
|---|---|
| 형식 | 8자, 대문자+숫자에서 헷갈리는 글자(0·O·1·I) 제외. 예 `K7PX3MWA` |
| 유효기간 | 발급 후 7일 |
| 사용 횟수 | 1회. 쓰이면 `used` 가 되고 누가 썼는지 남긴다 |
| 취소 | 마스터가 쓰이기 전 코드를 취소할 수 있다 |
| 입력 | 대소문자·공백 무시 |
| 실패 | 없는 코드·만료·사용됨·취소됨은 모두 `INVITE_INVALID` 하나로 답한다 (코드 추측 단서를 주지 않는다) |
| 제한 | 코드 등록 실패는 사용자당 1분 5회 → 429 |

## 초대 코드 보내기 (2026-09-25 추가)

사장님이 코드를 알바생에게 **휴대폰 문자 앱**으로 보낸다. 서버가 문자를 보내지 않는다 — 문자 발송 업체 계정·발신번호 등록·요금이 필요 없게 하려는 사용자 결정이다.

| 항목 | 규칙 |
|---|---|
| 버튼 | 사용 가능한 코드마다 "문자로 보내기" → 번호 입력(선택) → "문자 앱 열기". 공유를 지원하는 폰은 "공유"(카카오톡·문자 등 공유 시트)도 |
| 문자 본문 | `[매장 이름] 타임시트 초대` / `초대 코드: XXXX` / 안내 / 가입 링크 |
| 가입 링크 | `/join?code=XXXX` — 코드를 탭 안에 기억해 두고 로그인·가입 뒤 온보딩의 초대 코드 칸을 채운다. 등록에 성공하면 지운다 |
| 주소 형식 | `sms:<번호>?&body=<인코딩된 본문>` — iOS·Android 모두 읽는 형태. 번호는 숫자와 `+` 만 남긴다 |
| 대가 | 사장님 휴대폰에서만 문자 앱이 열린다(컴퓨터에서는 "복사"). 보내기 버튼은 사장님이 누른다 |

## 데이터가 서버로 옮겨간다

MVP 의 localStorage 저장([01](01-attendance.md))을 서버 DB 로 바꾼다. 급여 계산식([02](02-pay.md)·[03](03-overtime.md))은 그대로이고,
설정값이 어디에 있는지만 바뀐다.

| 값 | 전 (MVP) | 후 |
|---|---|---|
| 근무 기록 | 브라우저 | `shifts` 테이블, 멤버별 |
| 시급·1주 소정근로시간·소정근로일수 | 브라우저 설정 | **멤버별**, 마스터가 정한다 |
| 5인 이상 여부·매장 이름·위치 | 브라우저 설정 | 매장 설정, 마스터가 정한다 |
| 출근 알림 켜기 | 브라우저 설정 | 브라우저에 그대로 (기기마다 다르다) |

기존 localStorage 기록은 옮기지 않는다 (MVP 는 시험용).

## API

모두 Bearer 필요.

| 메서드·경로 | 누가 | 설명 |
|---|---|---|
| `POST /api/stores` | 소속 없음 | 매장 만들기 → 나는 마스터 |
| `GET /api/stores/me` | 소속 있음 | 내 매장 설정 |
| `PATCH /api/stores/me` | 마스터 | 이름·위치·5인 이상 |
| `POST /api/stores/me/invites` | 마스터 | 코드 발급 |
| `GET /api/stores/me/invites` | 마스터 | 코드 목록 (상태 포함) |
| `DELETE /api/stores/me/invites/:id` | 마스터 | 취소 |
| `POST /api/invites/redeem` | 소속 없음 | `{ code }` → 멤버로 소속 |
| `GET /api/shifts/me` · `POST /api/shifts/clock-in` · `POST /api/shifts/clock-out` | 멤버 | 자기 기록·출퇴근 |
| `GET /api/stores/me/members` | 마스터 | 멤버 목록과 급여 조건 |
| `PATCH /api/stores/me/members/:userId` | 마스터 | 시급·소정근로시간·소정근로일수 |
| `DELETE /api/stores/me/members/:userId` | 마스터 | 퇴사처리(화면 이름, 2026-09-25 "내보내기 말고 퇴사처리"). 소속만 지우고 기록은 남는다 |
| `GET /api/stores/me/members/:userId/shifts` | 마스터 | 멤버 기록 |
| `PATCH` · `DELETE /api/stores/me/shifts/:id` | 마스터 | 기록 수정·삭제 |

권한 오류는 403 `FORBIDDEN`, 다른 매장의 멤버·기록은 404 `NOT_FOUND` (존재를 드러내지 않는다).

## 수용 기준

| ID | 기준 |
|---|---|
| I-1 | 마스터가 발급한 코드를 멤버가 등록하면 그 매장 멤버 목록에 나타난다 |
| I-2 | 같은 코드로 두 번째 사용자가 등록하면 400 `INVITE_INVALID` |
| I-3 | 만료·취소된 코드도 `INVITE_INVALID` |
| I-4 | 이미 소속이 있는 사용자는 매장을 만들거나 코드를 등록할 수 없다 (409 `ALREADY_IN_STORE`) |
| I-5 | 멤버가 마스터 API 를 부르면 403 |
| I-6 | 다른 매장 마스터가 우리 멤버·기록을 조회·수정하면 404 |
| I-7 | 멤버 출퇴근이 마스터 화면에 반영된다 |
| I-8 | 이미 출근 중인 멤버가 또 출근하면 409 `ALREADY_CLOCKED_IN` |
