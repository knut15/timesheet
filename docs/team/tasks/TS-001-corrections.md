# TS-001 — 기록 수정 요청 팀 인수

- 상태: ready
- 범위: 기존 기록 수정 요청 작업을 인수하고 PRD 08의 멤버 요청 → 마스터 승인 → 기록·급여 반영을 검증까지 연결한다. 이번 팀 구성 작업에서는 기능을 재구현하지 않았다.
- 현재 담당: 다음 팀 실행의 시니어가 인수 확인 후 기획·디자인·구현 담당을 배정한다.
- 참고: [PRD 08](../../prd/08-correction-requests.md), [PRD 09](../../prd/09-leave-substitution.md), [검증 기록](../../verify/auth.md), [역할](../roles.md).
- 현재 코드: 등록 시점에 server/src/requests/, contract.ts, Prisma, pay.ts 등 기존 변경이 있었다. 동시 작업이 계속될 수 있으므로 시작 직전 git status·diff와 호출 경로를 다시 확인한다. 기존 작업을 완료 또는 누락으로 단정하지 않는다.
- 의존성: 로컬 테스트 서버·DB, 멤버·마스터·다른 매장 테스트 사용자. 운영 데이터는 사용하지 않는다.
- 범위 제외: 휴가·대타 전체를 새로 구현, 신규 인증 구조, 배포·외부 홍보. 기존 연계 코드의 회귀는 확인한다.

## 배정안 — 착수 전에 실제 소유권 확인

| 담당 | 책임·기본 파일 |
|---|---|
| 기획 | PRD 08의 정책·수용 기준, 원본 기록이 요청 후 변경된 경우의 처리 결정 확인 |
| 디자인 | 요청 탭과 승인 전후 비교 명세, 기존 timesheet-ui 규칙 |
| 시니어 | 요청 API·권한·트랜잭션, contract.ts·Prisma·API 생성물, 급여 연결 검토 |
| 주니어 | 확정된 계약에 따른 요청 화면·폼·목록. 실제 파일은 시니어가 지정 |
| QA | 테스트 소유권을 개발자와 나눈 뒤 C-1~C-7과 실제 사용자 흐름, docs/verify/corrections.md |
| 마케팅 | 이번 기능은 기본 참여 제외. 검증 후 변경 안내를 요청받으면 초안 작성 |

## 완료 조건

- PRD C-1~C-7 충족 증거가 있다. 승인·취소 경합, 원본 변경 후 승인 정책도 검증한다.
- 멤버 요청과 마스터 승인 화면이 연결되고, 거절·취소·빈 상태·실패 상태를 확인한다.
- 승인된 기록이 멤버 화면과 급여에 반영된다. 다른 매장·다른 사용자 접근을 거부한다.
- 관련 단위/API 검사, 타입·린트, 390px 브라우저 흐름의 결과를 구분해 기록한다.
- PRD·UI 규칙·API 생성물이 실제 변경과 일치한다. 필요한 검사가 미실시이면 done으로 표시하지 않는다.

## 검증

아직 이 카드로 실행한 검증 없음. 구현 현황 인수부터 시작한다.
수정·검증 0회. 새 증거 없이 같은 실패 2회 또는 수정·검증 3회이면 원인을 정리하고 해당 반복을 멈춘다.
