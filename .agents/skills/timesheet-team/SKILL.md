# timesheet 팀 운영

경로는 저장소 루트 기준이다. 먼저 CLAUDE.md, docs/team/README.md, docs/team/roles.md와 해당 작업 카드를 읽는다. 담당자에게는 해당 역할, 관련 PRD, 현재 변경, 허용 파일, 완료 조건만 전달한다.

## 작업을 시작할 때

- 사용자 요청의 범위를 확인하고 git status로 기존 변경을 확인한다. 다른 작업자가 수정 중인 파일은 소유권을 확인하기 전 덮어쓰지 않는다.
- 기존 작업이면 이어서 진행하고, 새 업무면 docs/team/task-template.md를 복사해 docs/team/tasks/에 등록하고 팀 목차에 연결한다.
- 부모 에이전트가 진행을 조정한다. 기술 분할·통합은 시니어 역할로 수행한다. 자식은 결과를 부모에게 반환하고 팀 전체를 다시 생성하지 않는다.
- 팀 요청은 필요한 역할에 위임할 수 있다는 뜻이다. 사용 가능한 동시 실행 슬롯 안에서만 실행하고, 별도 에이전트가 없으면 역할을 순차 수행했음을 명시한다. 자기 검토를 독립 QA로 보고하지 않는다.

## 진행과 되돌림

1. 기획이 PRD·수용 기준을 정리한다. 이미 확정됐다면 생략한다.
2. UI 변경이면 디자인이 상태별 화면 기준을 만든다. 시니어는 계약과 파일 소유권을 정한다. 의존성이 없는 조사만 병렬 진행한다.
3. 계약이 확정되면 시니어·주니어가 겹치지 않는 파일을 구현한다. contract.ts와 생성물은 시니어가 소유하며 export → gen:api 순서를 지킨다.
4. 시니어가 통합하고 QA가 PRD 기준으로 검증한다. 화면 변경은 디자인도 구현 화면을 검수한다.
5. QA 실패는 재현 절차·기대·실제·증거를 붙여 반환한다. 구현 오류는 개발자, 정책 모순은 기획, 사용성 문제는 디자인으로 보낸다. 기대값을 구현에 맞춰 낮추지 않는다.
6. 필요한 검증이 통과해야 done이다. 외부 환경 때문에 실행 못 했으면 review 또는 blocked와 이유를 남긴다. 마케팅은 검증된 기능만 초안에 반영한다.

## 상태·중단·기억

- 카드 상태: ready → in_progress → review → done. 수정은 review → in_progress, 의존성 부족은 blocked. 해결 후 이전 단계로 돌아간다.
- 같은 실패를 새 증거 없이 2회 반복하거나 한 작업의 수정·검증이 3회에 도달하면 작업을 분할하거나 원인·필요 정보를 보고하고 해당 반복을 멈춘다. 완료로 처리하지 않는다. 더 엄격한 사용자 실행 한도가 우선한다.
- 카드는 부모 에이전트만 갱신한다. 자식은 변경 파일·검증 결과·미해결점·다음 담당자를 반환한다. 다른 에이전트의 완료 보고를 받은 뒤 실제 산출물을 확인한다.
- 정책 변경은 PRD, UI 규칙 변경은 기존 timesheet-ui, 발견한 결함은 회귀 테스트에 반영한다. 확정된 반복 절차만 스킬에 반영하고 임시 가설을 영구 규칙으로 만들지 않는다.
- 모델·권한은 실행 환경을 상속한다. 역할명은 모델 성능 등급이 아니다. 병렬 실행을 위해 권한을 확대하지 않는다.
- 팀 구성은 배포·운영 DB 변경·외부 게시·메시지 발송의 새로운 권한이 아니다. 현재 사용자 지시의 승인 범위를 확인한다.
